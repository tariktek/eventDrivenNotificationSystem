# Security

How the system protects itself, what is checked automatically, and which
risks are accepted on purpose.

## Controls

| Area | Control |
|---|---|
| Authentication | API keys in `X-API-Key`, compared as SHA-256 digests in constant time against every configured key (no timing leak). Several keys can be active at once for rotation. Production refuses the development key and keys under 32 characters. |
| Input | Request bodies capped (`HTTP_MAX_BODY_BYTES`), strict JSON (unknown fields and trailing data rejected: a typo in a filter cannot widen a bulk operation), invalid UTF-8 and NUL bytes rejected, every field validated before anything is stored. |
| SQL | Static queries are generated by sqlc; the one dynamic query (listing with filters) only concatenates fixed column fragments, every value is a `$n` parameter. |
| SSRF (callbacks) | `https` only in production; the destination IP is checked **when connecting**, after DNS resolution (defeats DNS rebinding); private, loopback, link-local and other special ranges blocked; redirects not followed; environment proxies ignored. |
| Callback authenticity | `X-Signature: sha256=HMAC(secret, timestamp + "." + body)`; the timestamp is signed too, so captured requests cannot be replayed later (`callback.Verify` checks a 5-minute window). |
| Templates | Go `text/template` with an allowlist of functions, no `define`/`template`, no nested `range`, output capped at 256 KB: a template cannot be used to exhaust the server. |
| Errors | 5xx responses say only "An unexpected error occurred." plus a correlation ID; details go to the log. |
| Personal data | Recipients and content never appear in events, metrics or traces; the logger masks phone numbers and emails in every record (`+90555***4567`). Notifications are deleted 30 days after their final status (`RETENTION_NOTIFICATIONS`). |
| WebSocket | Same API key (header, or `api_key` query parameter for browsers; only paths are logged, never query strings); browser origin checked; per-client buffer and connection cap. |
| Containers | Distroless base (no shell, no package manager), non-root user, read-only root filesystem, all Linux capabilities dropped, `no-new-privileges`. |
| Configuration | Validated at startup, all errors reported at once; production refuses development secrets and insecure callback settings. |

## Automated checks (CI, every push)

| Check | Catches |
|---|---|
| golangci-lint with gosec | Insecure code patterns. Every `//nolint:gosec` carries its justification (reviewed: see below). |
| govulncheck | Known vulnerabilities in dependencies, limited to code the program can actually reach. Found two in `kin-openapi` (fixed by upgrading). |
| Trivy | Known vulnerabilities in the container image (fails on fixable HIGH/CRITICAL). |
| gitleaks | Secrets committed anywhere in the history. The public development defaults and one test fixture are allowlisted by value in `.gitleaks.toml` (by value, so the allowlist survives edits and history rewrites). |
| Dependabot | Weekly update PRs for Go modules, GitHub Actions and base images, vetted by the checks above. |

The scanners run from pinned images, not third-party actions: an action's
tags can be moved or removed (the Trivy action's tag disappeared while
this was built), which is a supply-chain risk of its own.

### Reviewed gosec suppressions

| Where | Why it is safe |
|---|---|
| `cmd/healthcheck` | The URL comes from the image's own `HEALTHCHECK`, not from input. |
| `cmd/worker` (breaker settings to `uint32`) | Validated to 1..1,000,000 and 1..1,000 at startup, so the conversion is exact. |
| `config.DevAPIKey`, `config.DevCallbackSecret` | Public development defaults, refused in production. |
| `middleware.HeaderAPIKey` | A header name, not a credential. |
| `math/rand` in the mock provider and the retry jitter | Fault injection and backoff spreading, not security. |
| `repository/postgres/templates.go` | The page size is capped at 100 before the conversion. |

## Accepted risks

Known limits, left out on purpose for this assessment, with what a
production deployment would do:

| Risk | Production answer |
|---|---|
| `/metrics`, `/health`, `/ready` and `/docs` are unauthenticated on the API port. | Serve them on an internal port or network only; probes and scrapers need no credentials. |
| No per-client request rate limit on the API (the provider rate limit protects the provider, not the API). | An API gateway or a Redis-backed per-key limiter in front. |
| One callback signing secret for all clients. | A secret per client (multi-tenant), rotatable. |
| API keys come from the environment; there is no key-management API. | A secrets manager, and keys stored hashed in the database with scopes. |
| docker compose serves plain HTTP and uses development passwords. | TLS terminated at the load balancer; real secrets injected at deploy time. |
| Delivery is at-least-once: a crash between the provider's 202 and recording it can resend a message. | The provider deduplicates by the `X-Idempotency-Key` header sent with every delivery. |
